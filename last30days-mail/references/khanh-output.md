After the badge and What I learned: label, use concise numbered key points. Each starts with one bold headline sentence. Group all references supporting that point as bullets directly underneath, using clickable [descriptive labels](<actual source URL>) on every host. Include dates and short engagement notes where useful. Never invent a URL or place references in a trailing Sources block. Preserve the ranked content angles afterward and the engine footer verbatim.

## TrueProfit discovery

Judge topics for Shopify merchants and dropshippers. Favor margins, fees, payouts, pricing, ad profitability, conversion, returns, cash flow and operations. Exclude developer/framework stories unless the evidence establishes a direct merchant consequence; do not rely on developer engagement alone.

For each supported topic, give:

- X article angle: a concise claim or hook.
- Website angle: a working title for a trueprofit.io blog post plus one sentence on its coverage.

Under each angle, include its own 2-4 on-topic, in-window reference posts with clickable links, dates and per-post engagement. A post may support both angles. Do not add a separate combined reference list, a podcast angle, or inflated aggregate Evidence totals. If fewer relevant sources exist, report the evidence limit rather than padding the list. Retain the honest nothing-solid outcome when nothing qualifies.

Write only id and x_article in each engine angles row; podcast is optional and can be omitted. Compose the Website angle in the final brief, outside the engine schema. Use evidence already returned; when it lacks sufficient backing posts, run a targeted per-topic search sequentially using the configured sources and preserve the same research window. Do not change channel configurations or take engagement totals from unrelated results. Discovery legs sharing a save directory must run sequentially because their handoff files overwrite one another.
