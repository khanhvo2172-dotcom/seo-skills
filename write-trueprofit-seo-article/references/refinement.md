# Refining an existing TrueProfit article

Use for requests to refine tone or implement senior/manager writing feedback. On Khanh’s PC, read the current manager-supplied skill at `E:/.trueprofit-claude-codex/shared/playbooks/trueprofit-blog-refine/SKILL.md`; its original remains private. The guidance below is a portable condensed adaptation, not permission to publish that original.

- Read the whole article and all relevant comment threads/replies, including resolved threads. Track each requirement as applied, preserved or pending. Content edits do not themselves resolve comments or accept/reject human suggestions.
- Use subject-led conversational advice, with varied subject/context openings. Avoid chains of imperative sentences and mechanically starting everything with “You”. Bold-label bullets explain a concrete action or consequence in a descriptive sentence. Preserve approved Why it matters / How to labels; apply an agreed peer-section structure across the complete set.
- Each heading, example, Why analysis and lesson should explain the same mechanism. Explain what an ad contains before analyzing it; distinguish observed creative from a proposed merchant test and unverified performance. General testing and profit cautions belong in the measurement section rather than every example.
- Core teaching sections need a principle, the relevant elements, a worked or before/after example and an explanation of when the advice applies. Measurement connects baseline → evidence → interpretation → decision, with attribution limits and possible confounders.
- Preserve exact headings/order, useful tables, numbers, calculations, dates, URLs/UTMs, credits, Content Highlight/Pro Tips and Further Reading unless the task explicitly authorizes the affected change. Keep the latest human wording and pending suggestions as the baseline.
- Check that process sections follow calculate → target → fair test → measure where relevant; fix a real logic problem without adding formulaic transitions. A conclusion should connect the advice to a practical next step without new claims, normally in 3–4 short paragraphs for this refinement workflow. Do not invent a missing heading under an outline lock.
- Use verified TrueProfit capabilities to address the article’s actual reporting problem and decision. Keep its article-specific CTA and omit pricing-plan promotion. Do not impose a fixed feature pitch on every topic.
- Keep live Google Docs images/crops/captions. Remove embedded base64 image payloads only from the Markdown companion, preserving image notes, captions and credits. Use shared gdocs.py for every Doc operation; deliver the clean Markdown companion for this refinement workflow and a brief Vietnamese handoff covering changes, logic fixes and remaining decisions.
- If the supplied local checker is available, run `python scripts/check_style.py <output.md>` from that private skill directory. It flags verb-first openings, em dashes and embedded image data, but is heuristic. Fix actual editable-prose problems; record protected blocks and false positives instead of changing approved copy or claiming an unqualified clean result. Do not invent the optional tone skill if absent.
