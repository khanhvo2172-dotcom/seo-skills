# Generate Response Mails to Partners

Keep the exact skill name requested by Khanh, including `reponse`.

## Gather context

Read shared memory and relevant partner preferences. Reuse completed domain-review results rather than running paid reports again. Identify the partner who supplied the domains by searching Gmail for distinctive domains, then read the original conversation. Inspect the latest partner reply, current terms and outstanding requests; distinguish old quoted messages from current instructions. If several conversations match and the correct recipient cannot be established, ask a focused question.

For a requested Gmail draft, reply in that same thread, preserving its subject, recipient and reply headers. Use the latest relevant partner message as the reply source. Avoid duplicates by checking existing drafts when needed. Drafting authorizes creating an unsent draft, not sending it. Do not modify tracking statuses to request-sent for an unsent draft.

## Write placement requests

Verify live publisher and TrueProfit target content. Use the user's selected publisher page and target URL for each requested placement, including selections recorded in the tracking Sheet. Flag overlapping requests through other partners without silently substituting another publisher page. An explicit anchor choice overrides the branded-anchor default; if the request is to link an existing word, preserve the sentence wording. Keep proposed additions to one or two sentences, matching surrounding prose. Prefer branded attribution such as linked `TrueProfit`, `TrueProfit's ...`, or `According to TrueProfit`. Describe a guide as a guide; do not invent research, reports, calculators, features or statistics.

Add a distinct, supported benefit. Check nearby publisher internal links: do not recommend TrueProfit as an alternative resource for the same task as the publisher's own guide. Preserve publisher recommendations and links. For example, beside an internal transaction-fees guide, explain monitoring net profit after costs rather than recommending another fee guide.

Format each deal with a numbered Page to insert link line containing the full clickable URL. Put the remaining fields on separate bullet points underneath (After, Add, Anchor text, Target page, or only the necessary edit fields). In HTML Gmail drafts, use actual ul/li elements for these bullets; keep the numbered page line outside the bullet list.

Use only the fields needed to implement the request:

- Insertion: Page to insert link; After (exact existing text); Add; Anchor text; Target page.
- Edit: Page to insert link; Current sentence; Updated sentence; Anchor text; Target page.

`After` means insert after the quoted existing text. Use Before or Placement only when necessary to remove ambiguity. Do not automatically fill every template field. Show publisher page URLs in full as clickable text. Hyperlink the proposed anchor to the target in the addition. Preserve wording already approved by Khanh unless a factual or placement issue requires correction.

When the TrueProfit target is a benchmark page, include relevant exact numbers or ranges from that live page in the proposed text, with attribution and the appropriate industry or business-model context. Do not replace numerical benchmarks with only vague wording such as depends on your industry.

## Availability checks

When asked to include pending or Follow-up Needed pages, verify the exact publisher URLs and status in the Exchange Links Tracking tab:
https://docs.google.com/spreadsheets/d/115RQOiTwbGPD7vKA7seHuERG5wdLuDmkQj4kM86GA7I/edit?gid=1225006563

Match normalized hostnames and publisher page URLs, not TrueProfit target URLs. Read the current headers rather than assuming a column schema. Do not imply the current partner handled earlier requests if another contact is recorded. In the email, list the relevant full URLs and ask whether they are currently available for exchange. Offer detailed requests after availability is confirmed. Do not include draft insertion text for those pages yet. If history cannot be verified, state that limitation to Khanh rather than inventing URLs or statuses.

## Compose and deliver

Open with a short natural greeting and acknowledgement. Include ready placement requests, then the availability question and page list, and a brief sign-off consistent with the thread. Keep internal statuses, Semrush metrics, tracking-row details and other partners' contact information out of the partner-facing email unless explicitly needed.

Use HTML for Gmail drafts so visible full URLs and proposed anchors are clickable. Do not paste Markdown syntax into an HTML email. Pass a real reply-message reference through the drafting tool; matching the subject alone is insufficient. Verify the returned draft recipient, subject and thread ID; correct the same draft if necessary rather than creating duplicates. Report the draft link and skill location. Send only if Khanh explicitly authorizes sending.
