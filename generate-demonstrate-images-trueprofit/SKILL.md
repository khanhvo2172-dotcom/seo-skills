# Generate Demonstrate Images — TrueProfit

Turn an article section into a clear visual explanation, or find a real example when authenticity matters. Khanh approved the bundled Shopify competitor-analysis v4 on October 21, 2026. It is a process-style reference, not a mandatory layout for every subject.

## Understand the requested deliverable

- Read the supplied heading and section before choosing the visual. For a whole-article request, read the current article and choose placements where images teach something; do not assume every heading needs an image.
- Use the live document/tab when supplied. Do not replace it with an older local draft. If source content is inaccessible, continue from available context and ask only for missing information that changes the result.
- Match scope: a sample request produces a sample; a narrow revision preserves unrequested elements; separate requested images remain separate files.
- Choose between a generated explanation, real screenshot, product image or campaign example. Read [sourcing-and-insertion.md](references/sourcing-and-insertion.md) when sourcing or inserting visuals.
- A request to create assets does not by itself request document/CMS edits. When insertion is requested or already authorized, complete it without an extra approval round.

## Preserve the approved visual language

- Light off-white/cool-gray canvas; generous whitespace; restrained framing.
- Rounded, regular-width geometric sans-serif typography. Black headings, concise regular-weight supporting copy and selective bold emphasis. The exact font family and color codes are unverified; do not claim otherwise.
- Simple flat black pictograms with pastel or restrained color accents. Prefer fewer meaningful icons over decorative vectors or detailed shaded UI/product scenes.
- **Use selective thick/thin line weight within each icon.** Keep most contours and inner details medium/light. Thicken selected base/right/lower edges, handle segments, frame portions or solid structural details. Keep open interiors. A global heavy outline on every edge was rejected.
- For processes, soft numbered circles, clear directional arrows, left-aligned labels/captions and spacious rows are useful reference features. Adapt the step count, reading sequence and layout to the content.
- Use soft mint, blue, sand, lavender and pink for process stages where appropriate. The broader library also uses green/teal, orange, charcoal and occasional red. Avoid harsh saturation; do not reduce the entire library to one fixed palette.
- Match the supplied TrueProfit wordmark/badge when branding is appropriate. Reference the actual branded image or a supplied logo asset; do not invent a replacement logo. Honor requests to remove branding on the current image.

## Condense the meaning into a visual brief

Write a short internal brief covering the concept, key relationships/sequence, exact image copy, composition, references, branding and output dimensions. Choose dimensions that support readability at article width; no universal ratio is established.

Rewrite and shorten article wording into labels rather than copying paragraphs. Preserve the essential meaning, qualifications and sequence. Keep labels large enough to read. Use concrete ecommerce situations where they help explain the concept.

Use verified article facts for numerical graphics. Reference images establish design, not current benchmark evidence. Check any new benchmark/date/source claim; do not invent a TrueProfit analysis, present fictional UI as real data, or draw quantitative geometry with misleading proportions.

## Generate or revise

Use the available native image-generation/editing tool and follow its current instructions. In Codex, apply the available `imagegen` skill for tool mechanics; if generation is unavailable, explain the limitation and provide a ready brief rather than claiming an image exists.

- Supply the relevant actual reference images to the generator, not just a verbal style description.
- For an edit, inspect and supply the latest target image, then describe the precise change and invariants. An icon-only revision should retain wording, typography, colors, circles, numbers, arrows, spacing and branding.
- For new graphics, omit edit-target parameters unless the tool requires references for style conditioning. Follow the tool's reference-input semantics.
- Keep distinct version filenames and the last approved version. Record the prompt used beside the delivered asset when useful for later revisions.
- If only a logo is wrong, correct that area using the real reference rather than rebuilding the entire image.

A useful process prompt fragment is provided in the visual guide. Treat it as guidance, not a fixed template.

## Review and deliver

Open the actual output and check:
- Meaning and coverage against the section; correct step order and unambiguous arrows.
- Exact labels, spelling, numbers and necessary qualifiers.
- No obscured, clipped or overlapping text; readable size at article width.
- Appropriate typography, spacing, pastel treatment and selective icon line weights.
- Logo integrity and consistent rendering quality.
- For a typography revision, compare the source, approved version and revision at the same article display width. Check the title, all subheads and captions. A changed file hash or tiny title adjustment is not evidence that the requested correction is visibly complete. Match reference scale, weight, wrapping and natural glyph proportions; do not claim an exact font-family change without evidence.

Fix material errors before delivery. Do not claim a new version is approved until Khanh approves it.
